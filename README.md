# claude-skills

Открытый каталог скиллов для Claude Code: проверенные, обезличенные, версионируемые инструкции, которые можно поставить одной командой и улучшать через pull request.

## Что такое скилл
Каталог с файлом `SKILL.md` (frontmatter + инструкции) и, при необходимости, `references/` (справочники) и `scripts/` (детерминированные проверки). Claude Code подгружает скилл по описанию и следует его протоколу. Формат — в [docs/skill-format.md](docs/skill-format.md).

## Скиллы

| Скилл | Назначение |
|---|---|
| [security-scanner](skills/security-scanner/) | Аудит безопасности кода и решений перед сдачей: SAST/SCA/DAST-анализаторы, 6 зон требований, пруфы из сканеров, план устранения `SECURITY_FIX_PLAN.md`; линтер CSRF по шаблонам |
| [critical-thinking-debug](skills/critical-thinking-debug/) | Протокол «виноват не мой код?»: перед выводом «причина внешняя» (библиотека, сеть, флаки, кэш…) запускает ≥3 независимых субагента; внешняя причина озвучивается только при валидных `NOT_FOUND` и позитивном доказательстве |

## Установка
Скопировать (или сделать симлинк) нужные скиллы в `~/.claude/skills/` (глобально) или `<проект>/.claude/skills/` (для одного проекта). Подробно и скрипты для Windows/Linux/macOS — [docs/installation.md](docs/installation.md).

```bash
git clone https://github.com/alexblag023/claude-skills.git
cp -r claude-skills/skills/security-scanner ~/.claude/skills/
```

## Структура репозитория
```
skills/<имя-скилла>/     # каждый скилл — отдельный каталог: SKILL.md, references/, scripts/
templates/skill-template # заготовка нового скилла
docs/                    # формат скилла, установка, чек-лист ревью
scripts/validate_skills.py  # проверка формата и утечек (запускается в CI)
.github/                 # CI, шаблон PR, CODEOWNERS
```

## Как добавить или изменить скилл
Коротко: ветка → правка → `python scripts/validate_skills.py` → pull request с ревью хотя бы одного коллеги. Подробности и правила — [CONTRIBUTING.md](CONTRIBUTING.md).

## Правила безопасности репозитория
- В скиллах **нет** секретов, токенов, персональных данных, названий клиентов/проектов и ссылок на внутренние документы. Это проверяет валидатор и ревьюер по [чек-листу](docs/review-checklist.md).
- Сторонний код допускается только с совместимой лицензией и записью в `THIRD_PARTY.md` скилла.
- Репозиторий публичный: всё, что попало в коммит, считается опубликованным навсегда (история git). Уязвимость в самом репозитории — см. [SECURITY.md](SECURITY.md).
