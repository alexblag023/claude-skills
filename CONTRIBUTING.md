# Как работать с репозиторием

## Добавить новый скилл
1. Создайте ветку: `git switch -c skill/<имя>`.
2. Скопируйте заготовку: `cp -r templates/skill-template skills/<имя>` (имя — `kebab-case`, совпадает с `name:` во frontmatter).
3. Заполните `SKILL.md` по [docs/skill-format.md](docs/skill-format.md). Описание (`description`) — самое важное поле: по нему Claude решает, когда применять скилл.
4. Добавьте скилл в таблицу в `README.md`.
5. Проверьте локально: `python scripts/validate_skills.py`.
6. Откройте pull request по шаблону; нужен approve минимум одного коллеги.

## Изменить существующий скилл
- Небольшие правки — прямо в PR. Меняете поведение протокола — опишите в PR, что и почему (какой случай не был покрыт).
- Если правка вызвана реальным инцидентом (пропущенная уязвимость, ложное срабатывание), опишите его **обезличенно**: без названий проектов, клиентов и людей.
- Скрипты в `scripts/` скилла проверяйте на положительном и отрицательном примере и приложите результат в PR.

## Правила содержимого (обязательные)
- Репозиторий публичный: никаких секретов, токенов, паролей, адресов внутренних систем, личных данных — история git хранит всё навсегда.
- Никаких названий клиентов, работодателей и закрытых проектов, ни пересказа или цитат внутренних документов; требования описывайте нейтрально по открытым источникам.
- Скиллы описывают **как** действовать, а гарантии даёт код: по возможности выносите проверки в детерминированные скрипты, а не в прозу.
- Сторонний код — только с лицензией, допускающей использование, и записью в `THIRD_PARTY.md` скилла (источник, авторы, лицензия, текст уведомления).

## Коммиты и версии
- Один коммит — одна логическая правка. Сообщения в стиле `skill(<имя>): что сделано` (`feat`/`fix`/`docs`).
- Версии скиллов — по семантическому версионированию в поле `version` frontmatter; заметные изменения записывайте в `CHANGELOG.md` скилла (если он есть).

## Что проверяет CI
`scripts/validate_skills.py`: корректный frontmatter, имя = имя каталога, наличие описания, отсутствие типовых секретов и слов из `scripts/denylist.txt`. Красный CI блокирует merge.
