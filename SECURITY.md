# Политика безопасности

## Что считать проблемой
- Секрет, токен, пароль или персональные данные, попавшие в репозиторий или его историю.
- Название клиента/проекта или пересказ закрытого документа в скилле.
- Скрипт скилла, выполняющий небезопасное действие (запуск недоверенного кода, отправка данных наружу).

## Что делать
1. Не обсуждайте находку в публичных каналах и открытых issue.
2. Сообщите владельцу репозитория лично или через приватный security advisory (Security → Advisories → Report a vulnerability).
3. Если утёк секрет — **сначала отзовите/ротируйте его**, затем чистите историю (`git filter-repo`) и force-push по согласованию с командой. Удаление коммита не отзывает секрет.

## Превентивные меры
CI (`scripts/validate_skills.py`) блокирует типовые секреты и слова из `scripts/denylist.txt`; включите GitHub secret scanning и push protection в настройках репозитория (Settings → Code security).
