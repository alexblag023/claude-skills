# Формат скилла

## Структура
```
skills/<имя>/
├── SKILL.md          # обязателен: frontmatter + инструкции
├── references/       # справочники, чек-листы, шаблоны (читаются по ссылке из SKILL.md)
├── scripts/          # детерминированные проверки (Python/Bash), запускаются скиллом
├── LICENSE           # если скилл лицензируется отдельно
└── THIRD_PARTY.md    # если есть сторонний код
```

## SKILL.md
```markdown
---
name: my-skill            # kebab-case, равно имени каталога
description: Что делает скилл и КОГДА его применять (триггеры, фразы пользователя).
---

# Название

Инструкции для Claude: когда срабатывает, протокол по шагам, формат результата, антипаттерны.
```

### Описание (`description`)
- Одно-два предложения: что делает и в каких ситуациях применять. Claude выбирает скилл именно по нему.
- Включайте типичные фразы-триггеры («аудит безопасности», «проверь перед сдачей»).
- Не длиннее 1024 символов.

### Тело
- Пишите как инструкцию исполнителю: шаги, критерии, формат вывода.
- Тяжёлые справочники выносите в `references/` и ссылайтесь по пути от корня скилла.
- Всё, что можно проверить программно, делайте скриптом (`scripts/`) с понятным кодом возврата (0 — чисто, 1 — находки): промпт описывает поведение, гарантию даёт код.
- Разделяйте факты и гипотезы, требуйте пруфы (вывод инструмента, `file:line`) для утверждений «работает/готово».

## Проверка формата
```bash
python scripts/validate_skills.py
```
Проверяет frontmatter, соответствие имени каталогу, длину описания, наличие типовых секретов и слов из `scripts/denylist.txt`.
