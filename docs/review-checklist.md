# Чек-лист ревью скилла

## Перед merge
- [ ] `python scripts/validate_skills.py` — зелёный.
- [ ] `name` во frontmatter = имя каталога; `description` говорит, **когда** применять скилл.
- [ ] Нет секретов, токенов, паролей, внутренних адресов, e-mail и ников людей.
- [ ] Нет названий клиентов, работодателей, закрытых проектов и ссылок на внутренние документы.
- [ ] Примеры и инциденты обезличены (не позволяют опознать проект или человека).
- [ ] Всё, что можно проверить кодом, вынесено в скрипт; скрипты проверены на положительном и отрицательном примере.
- [ ] Сторонний код: лицензия совместима, есть запись в `THIRD_PARTY.md` (источник, авторы, лицензия, уведомление).
- [ ] Скилл добавлен в таблицу в `README.md`.

## Ревью вклада от внешнего автора
Скилл — это инструкции для агента и исполняемый код, поэтому чужой вклад читается построчно, как код, идущий в продакшн.
- [ ] **Prompt injection в тексте.** В `SKILL.md`, `references/` нет скрытых указаний агенту: игнорировать правила, отправлять данные наружу, отключать проверки, выполнять команды «для настройки», обращаться к не заявленным URL. Проверить и невидимые символы, HTML-комментарии, длинные base64-блоки.
- [ ] **Скрипты.** Каждый скрипт прочитан целиком; делает ровно то, что описано в PR; нет сетевых вызовов, `eval`/`exec`, загрузки и запуска кода из сети, записи вне рабочего каталога, чтения `~/.ssh`, токенов, переменных окружения с секретами.
- [ ] **Команды установки** и примеры в документации безопасны (нет `curl … | sh`, `sudo`, `rm -rf` без ограничений).
- [ ] **Зависимости** новые, закреплены версиями, из известных источников; ссылки ведут на ожидаемые домены.
- [ ] **Права на вклад:** есть подпись DCO (`Signed-off-by`); для чужого кода указаны автор и лицензия в `THIRD_PARTY.md`.
- [ ] **Первый вклад автора:** запуск CI подтверждён вручную только после просмотра диффа.
- [ ] Дифф читается целиком, включая переименования, бинарные файлы и изменения в `.github/`.

## Публикация наружу
Перед тем как открыть репозиторий или отдельный скилл публично:
- [ ] Прогнать поиск по слову-маркерам организации и проектов (`scripts/denylist.txt` + ваш список) по всему дереву, включая историю git (`git log -p`).
- [ ] Прогнать `gitleaks detect --source . --redact` и `trufflehog git file://. --only-verified` по истории.
- [ ] Проверить, что внутренние документы организаций не пересказаны и не процитированы.
- [ ] Указан владелец в `LICENSE` (нет заглушек), проверены лицензии всех сторонних частей.
- [ ] Если скилл вырос из закрытого проекта — собирать публичную копию отдельно и обезличивать (не открывать рабочую историю).
