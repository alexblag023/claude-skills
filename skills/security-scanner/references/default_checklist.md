# Базовый чек-лист требований (по умолчанию)

Обобщённая планка ИБ на основе открытых источников (OWASP Top 10 / ASVS / API Security Top 10, CIS Benchmarks, NIST SSDF). Используется, когда пользователь не подключил собственный пакет требований (см. `requirements_guide.md`). Формат пункта: **id — требование → механизм-гарант → тип** (`CODE` / `INFRA` / `MANUAL`). Пункт выполнен только при наличии механизма-гаранта в коде/конфиге/инфре и пруфа (`file:line`, конфиг, вывод сканера).

## Z1 — Безопасная разработка ПО и веб-приложений
- **Z1-01 Инъекции.** Нет конкатенации недоверенного ввода в SQL/команды/XML/шаблоны. → параметризованные запросы/ORM, схема валидации на границе, правила Semgrep в CI. `CODE`
- **Z1-02 XSS.** Вывод экранируется по контексту. → auto-escape шаблонизатора, запрет `innerHTML`/`|safe` без санитайзера, CSP. `CODE`
- **Z1-03 Аутентификация.** Пароли хранятся только как хеш (argon2id/bcrypt/scrypt); лимит попыток входа; MFA для публичных/админ-интерфейсов. → единый auth-модуль, тест lockout. `CODE`
- **Z1-04 Авторизация.** Проверка владения объектом на сервере при каждом запросе (IDOR/BOLA), запрет mass assignment. → guard/policy-слой, allow-list полей, тесты «чужой id → 403». `CODE`
- **Z1-05 CSRF.** Защита всех state-changing форм/эндпоинтов при браузерном доступе (в т.ч. loopback и приложения без логина). Два слоя пруфа: (а) серверный гвард — токен-middleware или проверка `Origin`/`Sec-Fetch-Site` + TrustedHost, с тестом «чужой Origin → 403»; (б) статически видимый токен в каждой `<form method=post…>` и глобально для htmx/fetch — `python scripts/csrf_template_lint.py <корень>` → 0. `SameSite` у cookie-сессии. `CODE`
  - Запрещённые основания для `N/A`: «слушает только 127.0.0.1», «нет логина», «есть middleware». `N/A` допустим, только если нет state-changing эндпоинтов, достижимых из браузера.
- **Z1-06 Сессии и cookie.** Ограниченный TTL, серверная инвалидация при logout, `Secure`/`HttpOnly`/`SameSite`. → cookie-wrapper с безопасными дефолтами, e2e «после logout → 401». `CODE`
- **Z1-07 Секреты.** Нет секретов в коде и git-истории. → pre-commit gitleaks + блокирующий CI-гейт (gitleaks/trufflehog по истории), `.env` в `.gitignore`, секреты из env/secret manager. `CODE`
- **Z1-08 Криптография.** Современные алгоритмы (без MD5/SHA-1/DES/RC4/ECB), CSPRNG для токенов, проверка TLS-сертификатов не отключена. → allow-list алгоритмов, правило SAST на запрещённые примитивы. `CODE`
- **Z1-09 Исполнение кода.** Нет небезопасной десериализации (pickle/yaml.load), `eval`/`exec` недоверенного ввода. → правило SAST, безопасные загрузчики. `CODE`
- **Z1-10 SSRF, path traversal, загрузка файлов.** Allow-list хостов для исходящих запросов; канонизация путей и запрет `..`; проверка типа/размера файлов, путь сохранения не из ввода. `CODE`
- **Z1-11 Обработка ошибок.** Пользователю — общее сообщение без stack trace/секретов; fail-closed при сбое проверок безопасности. → глобальный error-handler, тест fail-closed. `CODE`
- **Z1-12 Веб-харденинг.** HSTS, CSP, `X-Content-Type-Options`, `frame-ancestors`/`X-Frame-Options`; CORS с allow-list; SRI для внешних скриптов; отключён листинг каталогов. → единый security-headers middleware, ZAP baseline. `CODE`
- **Z1-13 CI-гейты.** SAST, SCA и secret-scan запускаются автоматически и блокируют merge при High/Critical. → workflow с обязательными проверками, branch protection. `INFRA`
- **Z1-14 Цепочка поставки.** Lock-файлы в git, установка с хешами (`--require-hashes`/`npm ci`), GitHub Actions по SHA, образы по digest. `CODE`

## Z2 — Доступ и учётные данные
- **Z2-01 Наименьшие привилегии.** Роли и права минимально необходимые; админ-функции отделены. → RBAC-политика в коде/IAM. `CODE/INFRA`
- **Z2-02 Сервисные учётные записи.** Уникальные, не переиспользуются, ротация ключей. `INFRA`
- **Z2-03 MFA** для админ- и удалённого доступа. `INFRA/MANUAL`
- **Z2-04 Отзыв доступа** при завершении работ, блокировка неиспользуемых УЗ. `MANUAL`
- **Z2-05 Передача секретов** только по согласованным каналам, не в чатах/почте. `MANUAL`
- **Z2-06 Удалённый доступ** к чужой инфраструктуре — только с согласованием владельца среды. `MANUAL`

## Z3 — Уязвимости и конфигурация
- **Z3-01 Управление уязвимостями.** Регулярный SCA-скан; определённые сроки устранения по CVSS (задаются владельцем процесса). → Trivy/OSV в CI, отчёт JSON. `INFRA`
- **Z3-02 Базовый харденинг.** Нет debug-режима и дефолтных паролей в проде; контейнеры non-root, минимальные capabilities. → `hadolint`, `trivy config`, Checkov. `INFRA`
- **Z3-03 Управление изменениями.** Код-ревью, защищённые ветки, воспроизводимая сборка. `INFRA`
- **Z3-04 IaC и образы.** Скан конфигураций и образов на мисконфигурации и секреты. `INFRA`
- **Z3-05 Защита артефактов от вредоносного ПО.** Проверка дистрибутива антивирусом, подпись артефактов. `INFRA/MANUAL`
- **Z3-06 Транспорт.** TLS ≥ 1.2, без слабых шифров. → `testssl.sh`/`sslyze`. `INFRA`
