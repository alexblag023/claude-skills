# Схема вердикта эксперта-аудитора и правило гейта

## Формат ответа эксперта (обязателен)

```yaml
zone: "Z1 — Безопасная разработка ПО и веб-приложений"   # имя и номер зоны
object: "<что аудировали: репо/сервис/артефакт>"
summary: ZONE_PASS | ZONE_FAIL             # ZONE_PASS только при 0 FAIL

# таблица по КАЖДОМУ требованию зоны (ни одно не пропущено):
requirements:
  - id: "Z1-07"                              # id из пакета требований зоны
    ref: "Z1 / управление секретами"        # ссылка на пункт/семейство требований
    text: "секреты не хранятся в коде/репозитории"
    status: PASS | FAIL | N/A | MANUAL
    # при PASS — механизм-гарант и пруф:
    guarantee: "pre-commit gitleaks + CI secret-scan гейт"
    proof: ".gitignore:.env; .pre-commit-config.yaml:12; ci.yml:34 (job secret-scan) — прогон: 0 leaks"
    # при FAIL — чего не хватает + фикс-механизм:
    gap: "секрет openrouter в src/config.ts:8 в открытом виде; secret-scan в CI отсутствует"
    fix: "вынести в env + добавить gitleaks в pre-commit и CI-гейт, ротировать ключ"
    # при N/A — обоснование неприменимости
    # при MANUAL — что и кем подтверждается вне кода:
    manual: "ознакомление разработчиков с требованиями безопасной разработки под подпись — подтверждает владелец процесса/HR"
```

## Валидность вердикта

Невалиден и требует перезапуска эксперта той же зоны:
- `PASS` без непустых `guarantee` и `proof` (file:line / политика / строка конфига / вывод сканера);
- `FAIL` без `gap` и `fix`;
- отчёт, покрывающий не все требования зоны (пропущенные пункты);
- отчёт, где эксперт оценивает намерение/промпт вместо кода-механизма;
- ссылки на выводы другого эксперта.

## Правило гейта релиза

| Вердикты зон (валидные) | Решение |
|---|---|
| ≥ 1 `FAIL` в любой зоне | Решение НЕ готово к сдаче/деплою/доступу. Заложить механизм-гарант в код/инфру → перезапустить эксперта этой зоны. Пользователю не говорится «готово». |
| 0 FAIL, есть `MANUAL` | Условно готово. Явно перечислить организационные пункты, которые подтверждает человек/владелец; безусловное «готово» не выдавать. |
| Все зоны `ZONE_PASS`, MANUAL закрыты/вынесены | Разрешено «соответствие по зонам Z1–Z6 проверено, блокеров нет» — с указанием покрытия и ручных пунктов. |
| Отчёт зоны неполон | Зона не пройдена; перезапустить эксперта. |

## Результат наружу — отчёт об уязвимостях + план устранения, НЕ статистика

Таблица вердиктов выше — рабочий доказательный слой (нужен, чтобы `FAIL` был обоснован пруфом). Пользователю отдаётся НЕ она, а **отчёт об уязвимостях с предложениями по устранению**: каждый `FAIL` превращается в пункт «уязвимость/риск → что сделать → где (`file:line`) → критерий приёмки», ранжированный по реальному риску; дубли (одна находка в двух зонах) склеиваются в один пункт; `MANUAL` — в раздел «Ручное подтверждение». Точный формат и запреты (никаких таблиц статус, процентов, перечней N/A вместо инструкций) — в `../SKILL.md`, раздел «Обязательный формат результата». Поля `fix`, `gap`, `proof` из вердикта эксперта — сырьё для пунктов плана: `fix`+`gap` → «что сделать», `proof`/`location` → «где», а «критерий приёмки» формулируется как проверяемое условие закрытия (тест/grep/строка конфига/вывод сканера).
