# Схема вердикта субагента и агрегация

## Формат ответа субагента (обязателен)

```yaml
verdict: FOUND | NOT_FOUND
lens: code_hunter | architecture_auditor | adversarial_reproducer | assumption_auditor
confidence: high | medium | low

# при FOUND (findings может содержать несколько записей):
findings:
  - location: "path/file.py:123"            # файл:строка или компонент/граница
    mechanism: "что именно сломано и как это порождает симптом (причинная цепочка)"
    evidence: "доказательство: вывод запуска, минимальный репро, цитата кода, расхождение с документацией зависимости"
    fix_sketch: "1-2 строки: направление исправления"

# при NOT_FOUND (все три поля обязательны, иначе вердикт невалиден):
checked:
  - "перечень файлов/функций/границ/конфигов, которые реально открыты и проверены"
methods:
  - "какие проверки применялись: построчный проход, запуск репро, моки внешних систем, сверка с документацией, и т.д."
not_covered:
  - "что осталось непроверенным и почему (честная граница покрытия)"
```

## Валидность вердикта

Невалиден и требует перезапуска субагента с той же линзой:
- `NOT_FOUND` без непустых `checked` и `methods`;
- `FOUND` без `evidence` (голое подозрение — это не находка);
- ответ, в котором субагент обсуждает внешние причины вместо поиска внутренних (заражение гипотезой);
- ответ, ссылающийся на выводы другого субагента.

## Правило агрегации

| Вердикты (валидные) | Решение |
|---|---|
| ≥ 1 FOUND | Внешняя гипотеза отклонена. Воспроизвести находку → починить → перегнать тесты. Если находка не воспроизводится — понизить её до невалидной и перезапустить этого субагента. |
| Все NOT_FOUND, валидных < 3 | Протокол не завершён. Дозапустить субагентов до 3 валидных. |
| 3+ валидных NOT_FOUND | Разрешено заключение «ошибка в коде не выявлена». Далее — позитивное доказательство внешней причины. |

## Обязательный блок в ответе пользователю (при 3× NOT_FOUND)

```
Проверка внутренних причин (N независимых ревизий: код / архитектура / репро[ / допущения]):
— проверено: <суммарное покрытие из checked>
— в коде и архитектуре ошибка НЕ ВЫЯВЛЕНА (не «отсутствует»)
— не покрыто: <объединение not_covered>
Улики внешней причины: <версия зависимости, upstream issue, репро вне нашего кода, статус сервиса>
План: <воркараунд/пин версии/репорт upstream> + защита нашего кода от этого сбоя (валидация/таймаут/ретрай), т.к. отсутствие обработки внешнего сбоя — наш дефект.
```
